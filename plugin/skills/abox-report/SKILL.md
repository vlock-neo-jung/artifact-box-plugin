---
name: abox-report
description: Sends a report to the user's Artifact Box inbox with `abox report` when it is their turn: the work is done, stopped for their hands or a decision, or failed. Off unless the user asked for it in the session ("끝나면 알려줘", "화면으로 보고해", "report to my inbox when done") or instructions say so ("작업이 끝나면 abox로 보고한다"). Not for progress updates, each publish, or work another agent handed you (subagents, teammates, reviewers). Decision questions are abox-ask; publishing documents is abox-publish.

# Artifact Box 보고

보고는 에이전트가 「이제 당신 차례예요」라고 알리는 받은함 항목이다(아티팩트가 아니다). `abox report`로 올리면 그 워크스페이스 멤버 모두의 받은함(`/inbox`)에 들어가고, 알림을 켠 기기(휴대폰 포함)에 푸시가 뜬다. 에이전트는 답을 기다리지 않고 턴을 끝낸다.

사용자는 여러 작업을 동시에 돌리다가 휴대폰 푸시나 받은함에서 보고를 처음 본다. 그 작업을 모르는 사람이 제목 · 요약 · 다음에 할 일만 읽고 다음 행동을 할 수 있게 쓴다.

## 기본 규칙

- 모든 `abox` 명령에 `--json`을 붙이고 stdout의 JSON 하나를 읽는다.
- `abox` 명령은 한 번에 하나씩 실행한다. `;`·`&&`·`$(…)`로 다른 명령과 묶지 않는다.
- **작업 폴더**는 시스템 프롬프트가 세션 전용 임시 디렉토리를 알려 주면(예: Claude Code의 Scratchpad directory) 그 아래 `artifact-box/reports/`, 아니면 `/tmp/artifact-box/reports/`다. 보고 JSON은 여기에 보고마다 새 파일로 쓴다. 작업 디렉토리와 그 하위는 프로젝트 저장소일 수 있으니 파일을 만들지 않는다.
- `abox`는 Artifact Box 서버에 연결해야 한다. 에이전트의 샌드박스가 네트워크를 막는 환경(예: Codex 기본 설정)에서는 `abox` 명령을 네트워크가 열린 권한으로 실행하도록 승인을 요청한다.
- 보고는 고치거나 지울 수 없다. 올리기 전에 점검하고(아래 '4. 올리기 전 점검'), 같은 보고를 두 번 올리지 않는다.
- **워크스페이스는 사용자가 말할 때만 고른다**(`--workspace`, 고르는 법은 `abox-publish` 스킬의 '워크스페이스').
- 결과의 `warnings`는 이 문서에 없는 코드라도 `message`를 사용자에게 전한다.
- **로그인은 사용자가 직접 한다.** `abox login`·`abox logout`은 어떤 옵션으로도 실행하지 않는다. 사용자가 "로그인해 줘"라고 해도 같다. exit 3(`AUTH_REQUIRED`)이면 아래 문장을 그대로 전하고 멈춘다. `claude -p`·`codex exec`처럼 사용자가 없으면 이 문장을 결과로 남긴다. 사용자가 로그인했다고 하면 멈춘 명령부터 다시 한다. `error.message`가 `ABOX_TOKEN` 환경 변수를 가리키면 이 문장 대신 `error.message`·`error.hint`를 전한다.

  ```
  Artifact Box 로그인이 필요해요. 터미널에서 아래 명령으로 로그인해 주세요.
    abox login
  Claude Code에서는 입력창에 ! abox login 을 입력해도 돼요.
  주소가 나오면 브라우저에서 열어 Google로 로그인하고 승인해 주세요.
  원격 서버라면 그 주소를 아무 기기의 브라우저에서 열면 돼요.
  이미 로그인했는데 이 안내가 나오면, 에이전트를 돌리는 도구(Paperclip 등)가 설정 폴더를 바꾼 경우예요.
  그 도구의 에이전트 환경 변수에 ABOX_CONFIG_DIR=<홈 폴더 절대 경로>/.config/abox 를 넣어 주세요.
  ```

- **`abox` 설치·업데이트도 사용자가 한다.** 설치 스크립트와 `abox update`는 실행하지 않는다. `CLI_UPDATE_AVAILABLE` 경고는 `message`만 전한다. `abox`가 없으면(command not found, exit 127) 아래 문장을 그대로 전하고 멈춘다.

  ```
  Artifact Box CLI(abox)가 설치돼 있지 않아요. https://artifactbox.app/guide 의 설치 명령으로 설치해 주세요(Node.js 24 이상 필요).
  Claude Code 플러그인 · 스킬로 설치하는 방법도 같은 페이지에 있어요.
  이미 설치했다면 ~/.local/bin 폴더가 PATH에 있는지 확인해 주세요.
  설치한 뒤 다시 요청해 주세요.
  ```

## 언제 쓰나

기본은 꺼져 있다. 아래 둘 가운데 하나일 때만 보고한다.

| 언제                                                                     | 무엇을                                  |
| ------------------------------------------------------------------------ | --------------------------------------- |
| 사용자가 그 세션에서 말함("끝나면 알려줘", "화면으로 보고해")            | 그 세션 동안 보고하는 때가 오면 올린다  |
| 프로젝트 · 전역 지침에 "작업이 끝나면 abox로 보고한다" 같은 한 줄이 있음 | 말하지 않아도 보고하는 때가 오면 올린다 |

보고하는 때:

- 맡은 작업을 끝냈을 때
- 사용자 손이 필요해 멈췄을 때: 로그인 · 콘솔 작업 · 권한 부여처럼 에이전트가 대신할 수 없는 일, 그리고 결정 · 확인(push · 배포 등)을 기다릴 때
- 실패해서 더 진행하지 못할 때

결정 · 확인을 `abox-ask` 질문으로 올렸으면 보고하지 않는다(질문이 받은함 · 푸시로 알린다). 터미널에서 묻는 결정 · 확인은 턴을 끝내기 전에 「결정이 필요해 멈췄어요」 보고를 올린다. `abox-ask`가 꺼져 있을 때와, 켜져 있어도 예/아니오 · push · 배포처럼 `abox-ask`가 쓰지 않는 확인이 여기에 든다. 그 보고의 `next` 첫 줄은 터미널에서 정할 것이다(「main에 push할지 터미널에서 알려 주세요」).

보고하지 않는 때:

- 중간 진행 상황(「절반쯤 했어요」)
- 게시 하나하나. 문서 게시 · 새 버전 소식은 종이 알린다. 게시한 문서는 작업이 끝난 뒤 보고에 첨부한다
- `abox-ask`로 질문을 올린 결정
- 다른 에이전트가 맡긴 일(서브에이전트 · 팀원 · 리뷰어로 실행될 때). 결과는 그 에이전트에게 돌아가므로 보고하지 않는다. 사용자에게 직접 턴을 넘기는 에이전트만 보고한다
- 설명 · 질문에 답하기처럼 터미널의 답 자체가 결과인 짧은 요청(사용자가 그 요청에 보고하라고 했으면 보고한다)

## 보고 올리기

### 1. 올릴 곳 정하기

보고에 넘길 `--project` · `--workspace`를 정한다. 첨부는 보고와 **같은 워크스페이스**에 있어야 한다.

- **이 작업에서 게시한 문서를 첨부하면** 그 문서를 게시할 때 넘긴 `--project` · `--workspace`를 그대로 넘긴다.
- **그 밖에는** 아래 순서로 처음 맞는 프로젝트를 쓴다. 찾는 법은 `abox-publish` 스킬의 '프로젝트' 1 · 2와 같다.
  1. 사용자가 이번에 말한 프로젝트의 id(`abox project ls --json`의 이름과 맞춘다). 목록에 없으면 프로젝트를 만들지 않고 3으로 간다
  2. 레포 연결(`Artifact Box 프로젝트: <이름> (id: <id>)` 줄)의 id
  3. 둘 다 없으면 `--project`를 넘기지 않는다. 보고는 프로젝트 없이 올라간다(`미분류`에 들어가지 않는다)
- `--workspace`는 사용자가 워크스페이스를 말했을 때만 넘긴다. 레포 연결과 함께 쓸지는 `abox-publish` 스킬 '프로젝트'의 「사용자가 워크스페이스만 말했으면」 줄을 따른다(그 워크스페이스에 연결 id가 없으면 `--workspace`만 넘긴다).
- 보고에 붙이려고 새로 게시하는 문서도 여기서 정한 `--project` · `--workspace`로 게시한다. 사용자가 말한 프로젝트가 없어도 `abox project add`로 만들지 않는다.

레포 연결 id가 `NOT_FOUND`(exit 4)면 다른 곳에 대신 올리지 않는다. 연결 줄의 프로젝트가 지워졌거나 이 계정이 그 워크스페이스 멤버가 아니라고 터미널에 알리고 멈춘다.

### 2. 첨부 정하기

보고의 칸은 모두 짧은 한 줄이다. 설계 변경 · 측정 결과 · 오류 로그 · 긴 목록처럼 칸에 다 들어가지 않는 결과는 `abox-publish` 스킬의 규칙으로 문서(대개 Markdown)를 게시해 첨부한다. 이 작업에서 게시한 결과물(시안 · 정리 문서)도 첨부한다. 첨부는 없어도 되고 5개까지다.

- 첨부는 보고와 같은 워크스페이스의 아티팩트여야 한다('1. 올릴 곳 정하기').
- 캔버스는 `<URL>#board=<보드 파일>`로 보드 하나를, 슬라이드는 `<URL>#slide=<장 파일>`로 장 하나를 가리킬 수 있다(이 작업에서 고친 장 등).
- 질문 아티팩트는 첨부할 수 없다. 모음도 첨부할 수 없다(「모음은 첨부할 수 없어요. 안의 문서를 첨부해요」): 안의 문서를 원본 URL로 첨부한다. PR · CI · 이슈 같은 바깥 주소는 첨부가 아니라 `links`에 둔다.
- 관련 없는 아티팩트를 개수를 채우려고 붙이지 않는다.

### 3. 보고 쓰기

1. **틀을 받는다**: `abox report --example --json`의 `data`가 그대로 통과하는 보고 JSON이다. 칸 구성과 분량을 참고하되 예시 내용(결제 재시도)을 옮기지 않는다. 예시의 첨부 주소(`EXAMPLE0…`)와 바깥 링크는 자리만 채운 것이라 실제 값으로 바꾸거나 뺀다.
2. **작업 폴더에 새 파일로 쓴다**: `<작업 폴더>/<작업을 나타내는 이름>-report.json`(예: `payment-retry-report.json`).
3. **칸**: 모든 칸은 한 줄 평문이다. 줄바꿈은 거부되고, 여러 줄은 `next` · `done`의 줄로 쓴다. 화면은 백틱 인라인 코드만 그리고 굵게 · 링크 같은 Markdown은 글자 그대로 보인다. 앞뒤 공백은 지워지고, 글자 수는 UTF-16 길이(한글 한 글자 = 1)로 센다. 표에 없는 칸은 거부된다.

   | 칸            | 필수 | 한도                      | 쓰는 것                                                                         |
   | ------------- | ---- | ------------------------- | ------------------------------------------------------------------------------- |
   | `report`      | ○    | `1`                       | 계약 번호                                                                       |
   | `title`       | ○    | 1~80자                    | 무슨 일인지 한 문장. 받은함 행 제목과 푸시 제목이 된다                          |
   | `summary`     | ○    | 1~160자                   | 지금 어떤 상태인지 한두 문장. 접힌 행의 둘째 줄                                 |
   | `next`        | ○    | 1~3줄, 각 200자           | 받는 사람이 할 일, 가장 급한 것부터. 첫 줄이 푸시 본문이 된다                   |
   | `work`        | ○    | 1~200자                   | 어느 작업의 무엇인지(`<저장소 · 프로젝트> · <무엇을 하는 작업>`)                |
   | `done`        | ○    | 1~5줄, 각 200자           | 한 일. 결과 위주로                                                              |
   | `attachments` |      | 0~5개 `{url, note}`       | `url`은 500자, `note`는 1~200자 「이 첨부에서 무엇을 보면 되는지」              |
   | `links`       |      | 0~5개 `{title 1~60, url}` | 바깥 참고. URL은 https(로컬 서버면 localhost · 127.0.0.1 · [::1]의 http), 500자 |

4. **쓰는 법**
   - 그 작업을 모르는 사람이 읽는다고 보고 쓴다. 대화에서만 쓰던 이름 · 약어는 풀어 쓰고, 로컬 파일 경로보다 PR · 브랜치 · 문서 주소를 쓴다.
   - 끝낸 작업도 `next`에 받는 사람이 할 일(리뷰 · 머지 · 확인할 곳)을 쓴다.
   - 멈췄으면 `next` 첫 줄에 사용자가 해 줄 일을 메뉴 경로 · 명령 · 입력값까지 쓰고, 다음 줄에 그 뒤 어떻게 이어 가는지 쓴다(「로그인한 뒤 터미널에서 '이어서 해'라고 말해 주세요」).
   - 실패했으면 `title`에 실패를, `summary`에 원인과 어디까지 됐는지를, `next`에 사용자가 고르거나 해 줄 일을 쓴다. 오류 로그는 첨부로 둔다.
   - 비유 대신 조건과 수치로 쓴다(「테스트 24개 추가, 전체 통과」).
   - 화면과 같은 해요체로 쓴다.

   | 칸                 | 좋은 예                                                               | 쓰지 않는 예    |
   | ------------------ | --------------------------------------------------------------------- | --------------- |
   | `title`            | 결제 재시도 구현을 끝냈어요 · 운영 콘솔 로그인이 필요해 멈췄어요      | 작업 완료       |
   | `next`             | PR #42를 리뷰하고 main에 머지해 주세요                                | 확인 부탁드려요 |
   | `work`             | payments · PG사 일시 오류로 실패한 결제를 자동으로 다시 시도하는 기능 | 아까 말한 작업  |
   | `attachments.note` | 구현하면서 바뀐 결정은 3절, 알람 켜는 법은 2절에 있어요               | 참고 자료       |

### 4. 올리기 전 점검

보고 파일을 다시 읽고 아래가 **모두 「예」일 때만** 올린다. 하나라도 「아니오」면 고친 뒤 처음부터 다시 점검한다.

- [ ] 푸시에 보이는 것(제목 · 다음에 할 일 첫 줄)만 읽어도 무슨 일이고 무엇을 하면 되는지 안다
- [ ] 이 작업을 전혀 모르는 사람이 어느 작업인지 안다(`work`)
- [ ] `next`가 받는 사람이 할 행동이고, 가장 급한 것이 첫 줄이다
- [ ] 긴 결과는 칸이 아니라 첨부에 있고, 첨부마다 무엇을 보면 되는지 적혀 있다
- [ ] 예시의 내용과 자리만 채운 주소가 남아 있지 않다

### 5. 올리기

'1. 올릴 곳 정하기'에서 정한 `--project` · `--workspace`를 넘긴다. 정하지 않은 것은 넘기지 않는다.

```bash
abox report <작업 폴더>/payment-retry-report.json --project Pq4wT8nV2mK6rX9bL3cH7j --json
```

```json
{
  "ok": true,
  "data": {
    "id": "Rk3vX9pQ7mL4tB8nC1dE5f",
    "url": "https://artifactbox.app/inbox?report=Rk3vX9pQ7mL4tB8nC1dE5f",
    "workspace": { "id": "Wn3kQ7vR2xL9mT4pB8cJ6d", "kind": "personal", "name": "개인" },
    "project": { "id": "Pq4wT8nV2mK6rX9bL3cH7j", "name": "payment-service" }
  }
}
```

`project`는 프로젝트 없이 올렸으면 `null`이다.

### 6. 알리고 턴 끝내기

터미널의 마지막 답에 작업 결과와 함께 받은함 주소(`data.url`)를 줄이지 않고 한 줄로 남기고 턴을 끝낸다. 보고에 대한 답을 기다리거나 확인을 묻지 않는다. `claude -p`·`codex exec`처럼 사용자가 없으면 이 줄을 결과로 남긴다.

```
보고했어요 — https://artifactbox.app/inbox?report=Rk3vX9pQ7mL4tB8nC1dE5f
```

팀 워크스페이스(`data.workspace.kind`가 `team`)면 그 줄 끝에 `({팀 이름} 멤버 모두의 받은함)`을 붙인다. 멈춘 보고였으면 사용자가 해 준 뒤 말하면 멈춘 곳부터 이어 간다.

## 실패 처리

실패하면 stdout에 `{"ok":false,"error":{"code","message","hint"?,…}}`가 나온다. exit code로 판단하고, `error.hint`가 있으면 사용자에게 함께 전한다. 보고를 올리지 못하고 멈출 때도 작업 결과는 터미널에 알린다.

| exit · `error.code`                    | 뜻                                                                 | 할 일                                                                                                                                                                                                                                                                                                                        |
| -------------------------------------- | ------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 2 · `REPORT_INVALID`                   | 보고가 형식에 맞지 않거나 첨부가 맞지 않음                         | `error.issues[]`의 `path`(보고 JSON 안의 JSON Pointer: `/next/1` = `next` 둘째 줄, `""` = 보고 전체)를 `message`대로 고쳐 다시 올린다. 칸을 비우거나 내용을 빼서 통과시키지 않는다. 첨부 문제는 아래 표대로 고친다. 같은 오류(`path`·`code`가 같은 이슈)가 3번 반복되면 멈추고 `issues`와 보고 파일 위치를 사용자에게 알린다 |
| 2 · `INVALID_INPUT`                    | 사용법 오류, JSON 문법(`error.line` · `error.column`), 객체가 아님 | `error.message`대로 고친다. `--project`의 워크스페이스와 `--workspace`가 다르면 `abox-publish` 스킬의 '프로젝트' 규칙대로 하나만 넘긴다                                                                                                                                                                                      |
| 2 · `INVALID_INPUT` + `candidates`     | 같은 이름의 워크스페이스가 여럿                                    | 후보를 보여 주고 고르게 한 뒤 `--workspace <id>`로 다시 실행                                                                                                                                                                                                                                                                 |
| 3 · `AUTH_REQUIRED`                    | 로그인 필요                                                        | `abox login`을 실행하지 않고 '기본 규칙'의 문장을 안내한 뒤 멈춘다                                                                                                                                                                                                                                                           |
| 4 · `NOT_FOUND`                        | 프로젝트 · 워크스페이스 없음, 멤버가 아님                          | 레포 연결의 프로젝트면 '1. 올릴 곳 정하기'대로 알리고 멈춘다. 그 밖에는 id를 확인한다(`abox project ls --json` · `abox workspace ls --json`)                                                                                                                                                                                 |
| 5 · `LIMIT_EXCEEDED`                   | 요청이 64KB를 넘음                                                 | 칸에 넣은 긴 내용을 문서로 게시해 첨부로 옮긴다                                                                                                                                                                                                                                                                              |
| 6 · `NETWORK_ERROR` · `INTERNAL_ERROR` | 서버 연결 실패 · 서버 오류                                         | 샌드박스가 네트워크를 막아서라면 승인을 요청해 다시 실행. 아니면 한 번만 다시 실행한다. 또 실패하면 `error.message`·`error.hint`와 보고 파일 위치를 전하고 멈춘다                                                                                                                                                            |

첨부 문제(경로 `/attachments/0/url`)는 `message`가 알리는 경우대로 고친다.

| 경우                                         | 고치는 법                                                                                                                                                            |
| -------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 이 서버의 아티팩트가 아님(바깥 URL 등)       | 바깥 주소는 `links`로 옮긴다                                                                                                                                         |
| 없는 아티팩트 · 다른 워크스페이스의 아티팩트 | 보고의 워크스페이스('1. 올릴 곳 정하기')에서 `abox ls --json`으로 다시 찾는다. 없으면 그 워크스페이스에 게시해 첨부한다. 다른 워크스페이스의 것을 옮기는 명령은 없다 |
| 질문 아티팩트                                | 첨부에서 뺀다. 그 결정이 보고에 필요하면 결정 내용을 정리한 문서를 게시해 첨부한다                                                                                   |
| 모음 · 모음 항목 주소(`/a/<모음>/<번호>`)    | 안의 문서를 원본 URL(`abox info <모음 URL> --json`의 `data.items[].artifact.url`)로 첨부한다                                                                         |
| 캔버스가 아닌데 `#board=`가 붙음             | `#board=…`를 지운다                                                                                                                                                  |
| 그 보드가 캔버스의 지금 버전에 없음          | `abox pull <캔버스 URL> --out <작업 폴더>/<새 폴더> --json`으로 받은 `canvas.json`의 `boards[].file`에서 보드 파일 이름을 확인해 고친다                              |
| 슬라이드가 아닌데 `#slide=`가 붙음           | `#slide=…`를 지운다                                                                                                                                                  |
| 그 장이 슬라이드의 지금 버전에 없음          | `abox pull <슬라이드 URL> --out <작업 폴더>/<새 폴더> --json`으로 받은 `deck.json`의 `slides[].file`에서 장 파일 이름을 확인해 고친다                                |

## 참고

- 결정이 필요할 때(답을 기다리는 질문): **`abox-ask`** 스킬
