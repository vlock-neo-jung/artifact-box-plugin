# 질문 JSON

`abox ask --example <choice|open|opinion> --json`의 `data`가 종류마다 그대로 통과하는 틀이다. 이 문서는 칸마다 무엇을 쓰는지와 한도다. 서버는 이 규칙을 모두 검사해 맞지 않으면 `QUESTION_INVALID`로 칸 경로(JSON Pointer)를 알려 준다.

## 공통 규칙

- 계약 번호 `"question": 1`이 있어야 하고, 표에 없는 칸은 거부된다. 주제(`--url`)와 대체(`--revises`)는 JSON이 아니라 명령 옵션이다.
- 글자 수는 UTF-16 길이로 센다(한글 한 글자 = 1). 모든 칸은 앞뒤 공백을 지우고 검사하고, 줄바꿈 · 탭 밖의 제어 문자는 거부된다.
- 칸 성격은 셋이다.
  - **한 줄 칸**: 줄바꿈 거부. `label` · `title` · `background.summary` · `background.decide` · `flowTitle` · `flow[].text` · `flow[].note` · `terms[].term` · `options[].title` · `options[].summary` · `recommend.reason` · `attachments[].note` · `links[].title` · `examples` · `placeholder` · `outcomes[].answer` · `alternatives[].value`
  - **Markdown 칸**: `background.situation` · `options[].detail.how` · `recommend.detail.why` · 동의 구하기의 `detail`. 문단 · 소제목 · 목록 · 굵게 · 인라인 코드 · 코드 블록 · 인용 · 표 · 링크가 그려진다. raw HTML · 이미지 · Mermaid는 글자로 보인다. 링크는 https(로컬 서버면 localhost의 http)만 링크가 된다.
  - **평문 칸**: 그 밖의 칸. 줄바꿈은 살고 백틱 인라인 코드만 그려진다.
- 화면은 섹션마다 **요약 칸만 먼저 보이고** 상세는 펼쳐 본다. 요약 칸: 작업 맥락 `work.goal`, 질문 `title` · `background.decide`, 배경 `background.summary`, 옵션 `title` · `summary`, 추천 `recommend.reason`, 동의 구하기 `reasons`.

## 공통 칸 (모든 종류)

| 칸                                         | 필수 | 상한 · 쓰는 것                                                                                                          |
| ------------------------------------------ | ---- | ----------------------------------------------------------------------------------------------------------------------- |
| `question`                                 | ○    | `1`                                                                                                                     |
| `kind`                                     | ○    | `choice`(객관식) · `open`(주관식) · `opinion`(동의 구하기)                                                              |
| `label`                                    | ○    | 1~24자. 결정 목록 · 칩 · 알림에 쓰는 짧은 이름(「재시도 위치」)                                                         |
| `title`                                    | ○    | 1~80자. 질문 한 문장. 동의 구하기는 제안 문장                                                                           |
| `work.goal`                                | ○    | 1~200자. 어느 작업의 무엇을 하고 있는지                                                                                 |
| `work.done`                                | ○    | 1~5줄, 각 200자. 지금까지 한 것 · 정한 것                                                                               |
| `work.blocks`                              | ○    | 1~200자. 이 결정을 기다리는 다음 일(왜 지금 묻는지)                                                                     |
| `background.summary`                       | ○    | 1~160자. 지금 상황을 한두 문장으로                                                                                      |
| `background.situation`                     | ○    | Markdown 1~3,000자. 지금 상황 · 문제 · 제약                                                                             |
| `background.decide`                        | ○    | 1~200자. 이번에 정할 것                                                                                                 |
| `background.flowTitle` · `background.flow` |      | 흐름 제목 1~40자와 흐름 단계 2~8개. 둘 다 있거나 둘 다 없다                                                             |
| `terms`                                    |      | 0~10개 `{term 1~30, meaning 1~200}`. 처음 보는 사람이 모를 낱말. `term`은 겹치지 않게(대소문자 무시)                    |
| `attachments`                              | ○    | 1~5개 `{url, note}`. `url`은 500자, `note`는 1~200자 「이 첨부에서 무엇을 보면 되는지」                                 |
| `links`                                    |      | 0~5개 `{title 1~60, url}`. 바깥 참고. URL은 https(로컬 서버면 localhost · 127.0.0.1 · [::1]의 http), 500자              |
| `related`                                  |      | 질문 번호 0~5개, 겹치지 않게. 자기 번호보다 작고 주제에 있는 번호만(새 주제의 q1은 비운다). 「관련 결정」 칩으로 보인다 |

흐름 단계(`flow[]`)는 `{text 1~60, note 0~120, isNew?, gap?}`다. `isNew: true`는 이 옵션에서 늘어나는 단계, `gap: true`는 비어 있거나 이번에 정할 단계다.

## 객관식 `choice`

| 칸                                    | 필수 | 상한 · 쓰는 것                                                                      |
| ------------------------------------- | ---- | ----------------------------------------------------------------------------------- |
| `options`                             | ○    | 2~4개. `key`는 `A`부터 순서대로(`A` · `B` · `C` · `D`)                              |
| `options[].title`                     | ○    | 1~60자                                                                              |
| `options[].summary`                   | ○    | 1~160자. 이 옵션이 다른 옵션과 무엇이 다른지(무엇을 얻고 무엇을 내주는지) 한두 문장 |
| `options[].detail.how`                | ○    | Markdown 1~1,500자. 고르면 실제로 어떻게 동작하는지                                 |
| `options[].detail.changes`            | ○    | 1~6줄, 각 200자. 고르면 바뀌는 것(코드 · 운영 · 사용자)                             |
| `options[].detail.pros` · `cons`      | ○    | 각 1~5줄, 150자. 좋은 점 · 주의할 점                                                |
| `options[].detail.flowTitle` · `flow` |      | 바뀐 흐름 2~6단계. 둘 다 있거나 둘 다 없다                                          |
| `options[].attachments`               |      | 0~2개. 그 옵션의 시안 · 문서. 규칙은 `attachments`와 같다                           |
| `recommend.option`                    | ○    | 있는 옵션 키                                                                        |
| `recommend.reason`                    | ○    | 1~200자 한 줄 추천 이유                                                             |
| `recommend.detail.why`                | ○    | Markdown 1~1,500자. 추천 근거                                                       |
| `recommend.detail.points`             | ○    | 1~5줄, 각 200자. 근거 목록                                                          |
| `recommend.detail.revisit`            | ○    | 1~200자. 이 추천을 다시 검토할 조건                                                 |

## 주관식 `open`

| 칸            | 필수 | 상한 · 쓰는 것                                                     |
| ------------- | ---- | ------------------------------------------------------------------ |
| `outcomes`    | ○    | 2~5개 `{answer 1~40, effect 1~200}`. 답 범위마다 무엇이 달라지는지 |
| `examples`    |      | 0~5개, 각 1~60자. 누르면 답 칸에 들어가는 예시 답                  |
| `placeholder` |      | 1~80자. 답 칸 안내                                                 |

## 동의 구하기 `opinion`

| 칸             | 필수 | 상한 · 쓰는 것                                              |
| -------------- | ---- | ----------------------------------------------------------- |
| `reasons`      | ○    | 근거 1~6줄, 각 200자                                        |
| `changes`      | ○    | 동의하면 바뀌는 것 1~6줄, 각 200자                          |
| `concerns`     |      | 확인이 필요한 것 0~6줄, 각 200자                            |
| `detail`       | ○    | Markdown 1~1,500자. 의견 상세(확인이 필요한 것의 설명 포함) |
| `alternatives` | ○    | 검토했다가 버린 안 1~4개 `{value 1~60, why 1~200}`          |

## 첨부

- 받는 것: 같은 워크스페이스에 있는 아티팩트의 주소 `<서버>/a/<id>`(또는 id). 다른 프로젝트의 것도 같은 워크스페이스면 된다. 같은 아티팩트를 여러 질문에 붙여도 된다.
- 캔버스는 `<URL>#board=<보드 파일>`로 보드 하나를 가리킬 수 있다.
- 받지 않는 것과 그때의 오류 문구(경로 `/attachments/0/url` · `/options/1/attachments/0/url`), 고치는 법. 주제의 워크스페이스는 `abox info <주제 URL> --json`의 `data.workspace.id`다.

| 경우                                        | 문구                                                           | 고치는 법                                                                                                                                                                                           |
| ------------------------------------------- | -------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 이 서버의 아티팩트 주소가 아님(바깥 URL 등) | 이 서버의 아티팩트 주소가 아니에요                             | 바깥 주소는 `links`로 옮긴다. 결정에 그 내용이 필요하면 `abox-publish` 규칙으로 주제의 워크스페이스에 정리해 게시하고 그 URL을 첨부한다                                                             |
| 없음 · 다른 워크스페이스                    | 이 워크스페이스에서 찾을 수 없는 아티팩트예요                  | `abox ls --workspace <주제 워크스페이스> --json`(`--project` · `-q`)으로 주제의 워크스페이스에서 다시 찾는다. 없으면 그 워크스페이스에 게시해 첨부한다. 다른 워크스페이스의 것을 옮기는 명령은 없다 |
| 질문 아티팩트(자기 주제 포함)               | 질문 아티팩트는 첨부할 수 없어요. 앞 결정은 related로 가리켜요 | 첨부에서 빼고 같은 주제의 결정은 `related`(질문 번호)로 가리킨다. 다른 주제의 결정이면 그 내용을 정리한 문서를 게시해 첨부한다                                                                      |
| 캔버스가 아닌데 `#board=`                   | 보드 링크는 캔버스에만 붙여요                                  | `#board=…`를 지운다                                                                                                                                                                                 |
| 그 보드가 지금 버전에 없음                  | 그 보드는 지금 버전에 없어요                                   | `abox pull <캔버스 URL> --out <작업 폴더>/<새 폴더> --json`으로 받은 `canvas.json`의 `boards[].file`에서 보드 파일 이름을 확인해 고친다                                                             |

- 바깥 링크는 첨부를 대신하지 못한다. `links`에 둔다.
- 첨부는 질문을 올린 때의 버전으로 기록된다. 질문 뒤에 첨부를 고치면 화면이 「질문 뒤에 바뀌었어요」를 보인다.

## 한도

| 항목             | 한도                                                                   | 넘으면                                                     |
| ---------------- | ---------------------------------------------------------------------- | ---------------------------------------------------------- |
| 질문 하나        | 128KB. 들여쓴 파일이 아니라 정리한 JSON의 UTF-8 바이트(한글 약 4만 자) | `LIMIT_EXCEEDED`(exit 5). 긴 설명은 첨부 아티팩트로 옮긴다 |
| 주제 하나의 질문 | 100개                                                                  | `LIMIT_EXCEEDED`. 새 주제를 만든다                         |
| 첨부             | 질문마다 1~5개, 옵션마다 0~2개                                         | `QUESTION_INVALID`                                         |
